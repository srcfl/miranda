# Miranda v0.8.0-beta — UX roadmap ("a beta to be proud of")

> Builds on `docs/product.md` (the "bar for awesome") and
> `docs/superpowers/specs/2026-06-10-north-star-mesh-wallet-identity-design.md`.
> Status base: v0.7.0 (hardened core, relay + SPA live). This plan turns the
> hardened core into a beta led by UX.

## The goal

A stranger installs Miranda and reaches their live terminal from their phone in
under a minute. A returning user feels one terminal spanning all their devices.
Everything in this plan either shortens that path or removes a way it can fail.

## Definition of "proud beta"

The beta ships when this demo works in one unrehearsed take:

1. Fresh machine: one-line install → `mir up` → a pair QR appears. No second
   command, no docs.
2. Phone: scan → passkey → compare the safety number → live terminal.
   **Under 60 seconds from install.**
3. Start an agent or build in tmux. Pocket the phone, walk away. On a laptop
   browser: the machine is listed, tap it, the same session appears. **Under 3
   seconds.**
4. Kill Wi-Fi mid-session → cellular: the session resumes by itself, with an
   honest status pill meanwhile. **Under 3 seconds.**
5. A second machine joins; switch between machines without losing either.
6. Retire a machine: one tap revokes it, and it is gone from every device.

### Measurable gates

| Gate | Target |
|---|---|
| Time to first terminal (clean macOS + Ubuntu) | < 60 s |
| Reconnect after sleep / network flip (p90) | < 3 s |
| Successful continuation across the NAT matrix | ≥ 95 % |
| Passkey matrix (iOS/macOS Safari, Chrome desktop + Android, Firefox; iCloud Keychain + 1Password) | green |
| User-facing failures | every one ends in a plain sentence + one next step, never a raw error |

## UX principles for this beta

- **The demo is the spec.** Every slice must shorten the magic moment or remove
  a way it fails.
- **Friction only at trust decisions** (pair, revoke). Zero friction everywhere
  else — reconnect, switch, resume.
- **Honest states.** Never spin forever. Say what is wrong and what to do next.
- **Phone-first.** Every flow must work one-handed on a phone.

## Tracks and slices (PR-sized)

### Track U — the first minute

| # | Slice | Today | Acceptance |
|---|---|---|---|
| U1 | **`mir up` pairs inline.** With no owner pinned, the first `mir up` prints the pair QR + web URL itself and waits. | `mir up` says "Next: pair an owner"; pairing is a second command (`mir pair`). | Install → `mir up` → scan → terminal, without reading docs. |
| U2 | **tmux bootstrap.** If tmux is missing, offer to install it (detect brew/apt) or fall back with one honest line on what is lost. | A one-line warning at enroll (`agent_cmds.go:40`). | Clean machine reaches a persistent session without the user learning what tmux is. |
| U3 | **SPA empty state.** No machines → show the copyable install one-liner and "waiting for your first machine…", which resolves live when the machine registers. | A bare list. | Pair a first machine driven entirely from the phone screen. |

### Track R — reconnect feel and the live workspace

| # | Slice | Today | Acceptance |
|---|---|---|---|
| R1 | **Resume < 3 s.** Tune ICE failure detection and TURN failover; keep the session warm through sleep; measure p90. Status pill: online / reconnecting / offline, each with an action. | Auto-reconnect works; feel and timings unmeasured. | Wi-Fi → cellular flip resumes < 3 s p90; the pill never lies. |
| R2 | **Warm multi-machine in the SPA.** A machine strip beside the tmux window strip; background machines stay attached (bounded, ~3); switching is instant. | The SPA attaches one machine at a time; switching tears down the session (`app.js:646`). CLI already does this (`mir attach a b c`). | Two machines live in one browser tab; switch < 200 ms; neither session drops. |
| R3 | **Instant window strip.** Push tmux window changes via tmux hooks; drop the 1 s poll. | 1 s snapshot poll (`agent/session.go:48`, noted as a later optimization). | New window / activity shows < 200 ms after the tmux event. |

### Track N — names, care, and honest failure

| # | Slice | Today | Acceptance |
|---|---|---|---|
| N1 | **Machine rename** from SPA + CLI, propagated through the encrypted registry (local wins preserved). | Names fixed at `mir up --name`. | Rename on the phone; the new name appears on every device; the relay still sees nothing. |
| N2 | **Retirement flow.** "Retire machine" in the SPA = signed revocation with plain copy on what it means; re-pairing is guided. | Revoke exists (`⊘`) but the flow and copy are thin. | A non-expert retires a machine and understands what happened. |
| N3 | **Error taxonomy.** Audit every user-facing failure path (CLI + SPA) into a plain sentence + one next step; `mir doctor` covers each cause. | `mir doctor` exists; failure copy is uneven. | The gate above: zero raw errors reach a user. |

## Suggested order

U1 → R3 → R1 → N1 → U3 → R2 (the big one) → N2 → N3 → U2 → P1 → P2 → B1 → B2.
P3 runs in parallel from day one. Each slice is one PR with tests; the
byte-identical Go↔JS gate applies as always.

## Not in this beta

C3 federated relays, C4 DHT, Track D cross-wallet delegation, pane-level tmux
control, and every non-goal in `docs/product.md`. The beta bar is depth on the
five promises in "Scope discipline", not breadth.
